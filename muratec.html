Likely questions

高機率問題與回答方向

為什麼應徵技術支援，而不是純軟體開發？
我喜歡把問題從現象追到資料、系統與程式原因，不只寫完功能。這份工作若能結合系統設定、故障分析、SQL／程式修改與客戶溝通，會符合我的問題解決方式；我也會在面試確認各部分的實際比例。
你如何處理客戶回報的系統異常？
先確認影響範圍、時間、環境與最近變更，保存 log 並建立可重現案例；再區分設備、網路、資料庫、應用程式與操作流程，逐層排除。修正後以原案例及相關功能回歸測試，並留下處理紀錄。
沒有自動搬送設備經驗怎麼辦？
我不會把海洋資料經驗直接說成設備經驗，但資料流、時間同步、狀態紀錄、API／資料庫與問題追查方法可以移轉。入職後會先熟悉系統架構、訊息流程、標準操作與既有故障案例，再從可驗證的小任務開始。
日文能用到什麼程度？
我具 JLPT N2，可閱讀一般技術文件與電子郵件；口語反應仍需透過實務持續加強。我可以先以準確書面溝通、術語整理與會前準備確保資訊不失真，不會宣稱已達商務口譯程度。
能接受無塵室與現場支援嗎？
可以配合事先安排的現場作業，但希望先了解頻率、單次時數、輪值／on-call、加班補休與安全訓練。確認制度後，我能依團隊流程配合。
期望薪資是多少？
若表單只能填單一數字：月薪新臺幣 50,000 元。
面試時回答：「依我的碩士與資訊工程背景、日文能力，以及此職務包含系統支援、故障分析與客戶現場協作，我期望月薪約 50,000 元；仍可依實際工作內容、年終、輪值、加班費與出差津貼等整體條件討論。」不要主動報最低可接受數字。

Technical refresh

面試前複習

SQL

JOIN、GROUP BY、子查詢、交易與鎖定、如何從 log 與資料表追查異常狀態。

Windows／網路

服務、process、port、IP、基本 TCP/IP、權限、事件紀錄與設定檔。

程式除錯

重現條件、log、錯誤邊界、版本差異、rollback 與 regression test。

自動化概念

搬送任務、設備狀態、主機與控制端訊息、告警、復歸與 24 小時可用性。

今天新增的答題規則：遇到架構或效能題，先確認規模與要求，再依「資料流 → 失敗處理 → 量測 → 驗證」回答。開啟共用兩分鐘訓練
情境題：搬送任務偶爾延遲，怎麼查？
我會先確認影響設備、任務 ID、開始時間、頻率與最近變更，再把上位系統送單、任務 queue、資料庫狀態、網路訊息及設備回報串成同一條時間線。接著比較正常與異常 log，量測每一段 latency，不先認定是資料庫或設備。若影響生產，先依 SOP 降級或人工復歸；找到原因後重跑原案例、尖峰負載與告警測試，並補上 correlation ID 與分段監控。
情境題：如何設計 24 小時設備告警流程？
設備事件先帶時間、設備 ID、錯誤碼與任務 ID 進入事件處理層，完成格式驗證、去重與嚴重度判斷，再寫入狀態與歷史紀錄；需要處置的事件才通知值班或觸發既定復歸流程。重複事件以唯一鍵或 idempotency key 避免重複執行；外部通知設定 timeout 與有限 retry。監控至少包含告警量、處理延遲、失敗率與未結案數。
效能題：畫面慢，但平均 API 只要 200 ms
平均值可能掩蓋少數慢請求。我會看 p50、p95、p99、錯誤率與尖峰同時請求，再用 request ID 拆分應用程式、資料庫、外部設備與網路耗時。只有確認瓶頸後才做索引、批次、快取或非同步，最後用相同負載比較改善前後。

Questions to ask

一定要反問

  1. 日常工作中系統規劃、程式／SQL、測試、文件與客戶現場各占多少？
  2. 目前主要技術棧、資料庫及版本管理工具是什麼？新人會修改程式碼嗎？
  3. 故障發生時由誰第一線接手？是否需要夜間、假日或輪值 on-call？
  4. 無塵室與國內客戶現場的頻率、單次天數、工時及補休如何安排？
  5. 日文主要用於郵件、會議或赴日訓練？公司是否提供語言與產品訓練？
  6. 新人前三個月的訓練、mentor、文件與實作任務如何安排？
  7. 核薪區間、試用期、年終、加班費、出差津貼與調薪制度為何？
