論文怎麼和這份工作連起來？

我的研究不是開發海流預報模型，而是把不同來源的資料做成可查詢、可驗證的流程。Python 負責資料解析與配對，PostgreSQL 保存結果，Flask 提供 API，QGIS 呈現圖層。困難在於時間、單位與資料定義不一定相同，不能只是把資料相減。我會保留來源，從輸出回查原始資料，再核對重算結果。這種把重複檢查變成工具、並驗證結果的經驗，是我想延伸到工程自動化的部分。

  1. 前 30 秒：問題與目標，不同格式和批次難以回查。
  2. 接著 60 秒：畫出資料 → Python → 資料庫 → API → QGIS，說出各部分的責任。
  3. 接著 60 秒：選一個實際遇到的時間或單位問題，說怎麼發現、修正與核對；只講自己能解釋的細節。
  4. 最後 30 秒：連結自動化檢查與工具維護，坦白新領域仍需學習。

一致性核對只證明被檢查項目一致，不等於所有程式都沒有錯，也不等於已具備 PCB 設計能力。

先練基礎，不要硬背框架

以下是依職務與你過去面試弱點設計的練習，不是研華已確認會考的題目。

API 少了一個欄位，怎麼處理？

我先確認是整個請求失敗、回傳 JSON 少欄位，還是非同步工作尚未完成。查看狀態碼、回傳內容和日誌，再往查詢、轉換與序列化追查。必填欄位缺失就報错或隔離；可選欄位依規格處理。暫時性失敗才考慮有限次重試，寫入則要避免重複執行。

不要先加 sleep。缺欄位不一定是「太快丟包」；p50／p90 描述延遲分布，也不是缺值原因。只有確認需要等待非同步結果後，才討論有期限的輪詢或完成通知。

def require_value(payload):
    if "value" not in payload:
        raise ValueError("missing value")
    if payload["value"] is None:
        raise ValueError("null value")
    return payload["value"]

assert require_value({"value": 0}) == 0
assert require_value({"value": 12}) == 12

in 查鍵是否存在；is None 查空值；0 仍可能是合法資料。這段是假設 value 必填且不可為 null 的示例，正式系統還要做型別、範圍驗證與錯誤回應。

函式沒有 return，會怎樣？

一般 Python 函式執行到底未 return，回傳 None。print 只是印出文字，不是回傳值。檢查 if／else 每條分支，再測正常值、空資料和錯誤輸入。

def double(value):
    return value * 2

assert double(0) == 0
assert double(3) == 6
如何設計一個自動檢查工具？
  1. 先向工程師確認輸入、規則、輸出和不可自動判定的情況。
  2. 讀取資料，先驗證格式、必要欄位與單位。
  3. 將檢查規則獨立成可測試的函式。
  4. 輸出問題位置、規則與原因，保留原始檔；不要直接覆寫設計。
  5. 以工程師確認的正常與異常案例，比對漏報與誤報。
  6. 小範圍試用，保留版本與回復方法後再擴大。

這是你會採取的設計步驟，不要說已在 Cadence 實作過。

工具跑很慢，你會先改什麼？

我先記錄資料量和各階段耗時，分辨是讀檔、API、資料庫還是計算慢，再選一個瓶頸改善。例如重複呼叫可以評估批次處理，重複掃描可評估字典索引。修改前後用相同資料比較時間和結果，不會一開始就加多執行緒。

你都用 AI，怎麼確認程式是對的？

我會先確認規格和輸入輸出，請 AI 協助拆解或提出修改，再自己閱讀差異、跑小案例與邊界測試，必要時回查原始資料。我不會把程式能執行當作正確，也不會把公司設計檔直接送到未核准的外部 AI 服務。不確定的部分會請同事 review。

現場不會寫，怎麼開口？

我先確認一下輸入、預期輸出，以及空值要怎麼處理。這個語法我目前不熟，能先用 Python 或偽碼說明嗎？我會先做最簡單可行的版本，用小例子逐步測試，再討論效能。

使用 AI 前先問面試官是否允許；未獲允許時不要偷偷查工具。
