先篩待遇，再決定是否遞件

9/18 重評：目前沒有足夠證據，支持用下列任一機會取代已取得的 offer。本場多為廠務、施工與控制職，不是每份「自動化」都比智慧製造／資料整合更貼近你的背景。先保留既有選項，再找能提出更好書面條件的公司。個人 offer 與薪資明細不公開在此頁。

每家先用兩分鐘確認

  1. 固定待遇：新人底薪與無條件固定津貼各多少？不加班、不輪班、不派駐時，每月能領多少？
  2. 保證年薪：年終幾個月有書面保證、以底薪還是全薪計算？首年按比例及發放條件為何？分紅另列，不當保證。
  3. 工作代價：實際廠址、通勤或租屋、平均加班、夜間待命與出差天數？不能用額外工時換來的收入當成加薪。
  4. 發展內容：新人前三個月做什麼？誰帶？控制程式、資料整合與測試占多少？避免只換成施工或維修職。
  5. 下一步：能否初步說明碩士新人核薪區間、面試流程與預計核薪時間？先取得資訊，再決定是否安排面試。

「我想找自動化軟體或資料整合的新人職，期望固定月薪約 56,000 至 60,000 元，加班費另外計算，也會綜合比較保證年薪、工作地點和培訓。請問這個職缺的碩士新人核薪範圍，是否有機會接近這個條件？」

56–60K 是談薪目標，不是市場行情或錄取保證，也不等於月薪達標就一定更好。固定年收入先以「固定月薪 × 12 ＋ 書面保證獎金」比較，再看額外生活成本與工時。先確認現有津貼是否固定；不同薪資口徑不能直接相乘。

  1. 矽科宏晟，先確認三重儀電：有經歷不拘的具體北部職，但必須問清出差、施工比例與加班。公開 33–70K 不代表新人待遇勝出。

  4. 漢唐，僅保留具體新人職：活動主力是資深職，其他監控職也可能是監工，不因品牌優先。

以上是「值得花時間取得資訊」的順序，不是入職排名。若要保留程式與資料能力，士林資訊職比純儀電更直接；若願意轉控制現場，才把矽科儀電放前面。

可以不遞：若待遇上限明顯不符目標、主要工作不合方向，或只靠加班／海外補助才有高收入，就禮貌結束。待遇未知則記錄「待核薪」，不直接判定好或壞。新的書面條件未到手前，先確認既有 offer 的回覆與報到期限，不急著放棄。

什麼條件才值得換

  • 財務：不含加班／輪班／派駐的固定月薪，以及扣除新增通勤、租屋成本後的書面保證年收入，至少能說明改善在哪裡。較低月薪不能拿未保證分紅補足。
  • 工作：有具體開發、資料串接或控制整合任務，有人帶；不是主要做施工、配線或維修卻只換了職稱。
  • 界線：平均與旺季工時、出差比例、待命和補償清楚；公開裁罰要問改善，不視為無關。
  • 落地：職缺、廠址、雇主與核薪有書面依據。只有面談機會，不能與已取得的 offer 當作同一成熟度選項。

能談：若工作包含中央監控資料或告警紀錄，可用論文的時間索引、查詢與回查經驗介紹自己；不是已做過 SCADA。

你怎麼介紹自己

您好，我是資工學士、通訊碩士，今年剛畢業。碩士專案使用 Python、PostgreSQL 和 API 整合資料，做過時間配對、品質檢查、查詢與結果驗證。我想找自動化軟體、設備資料整合或測試開發的新人職。PLC 和現場控制尚無實務經驗，所以想了解你們會怎麼培訓，以及新人第一個專案的工作內容。

用 60 秒講論文

「我的研究不是訓練海流模型，而是把不同日期、格式、時間與位置的資料整理成可查詢、可驗證的系統。我用 Python 處理資料，PostgreSQL 保存結果，Flask API 提供查詢，最後用 QGIS 檢視。這段經驗可延伸到設備資料與異常回查，但我不會把資料分析經驗直接說成已經會操作工業控制設備。」

自動化工作要分清楚
  • 資料／流程自動化：Python、API、SQL，最接近目前作品。
  • PLC／HMI：控制邏輯與人機介面，需要補控制基礎與安全觀念。
  • SCADA／監控：設備狀態、告警、歷史資料與系統串接；實際仍可能含現場測試。
  • 機電／儀電：可能包含配線、安裝、維修及試車，不保證以寫程式為主。
  • 工程案 PM：常重進度、分包商、工安與驗收；不同於軟體產品 PM。
可能聊到的基礎題 · 練習，非公司考古題

設備資料沒更新怎麼查？先確認範圍與最後正常時間，分別查看來源是否有送、網路／服務狀態、API 回應與欄位、資料庫寫入及畫面刷新。保留日誌，先在測試環境重現；不要直接重啟或修改生產控制。

不會 PLC 怎麼回答？「我目前強項是資料處理、SQL 與 API，尚無獨立 PLC 專案經驗，希望先了解團隊使用的控制平台、培訓與安全操作流程。」

AI 怎麼協助？用來理解文件、整理測試案例與除錯假設，仍需驗證程式與資料；不把公司機密或控制參數直接交給外部工具。

  6. 面試與投遞期限，今天現場收履歷後是否還要網路應徵？
