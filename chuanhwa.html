從你的技術轉到 .NET/Vue 的說法

我目前主要是 Python/Flask 和 QGIS，不會把自己說成 .NET/Vue 即戰力。不過 REST API、資料庫、前後端資料契約、空間資料格式與版本控制的概念可直接轉移。我會先從既有 API、資料模型和小型修正進入，再補 C#、Entity Framework、Vue 元件與 ArcGIS Maps SDK。

政府 GIS 專案常見的工程問題
  • 資料來源與版本多，欄位、座標和更新日期需追蹤。
  • 權限、稽核、資訊安全與交付文件不能忽略。
  • 需求由業務單位提出，需轉成可驗收的技術規格。
  • 系統維護期長，舊技術與新架構可能同時存在。
  • 不要只追求畫面完成，需保留測試資料和重現方式。

Interview Q&A

高機率問題與答法

為什麼不直接應徵全端 GIS 工程師

我看到全端職缺要求兩年以上以及 .NET/Vue/ArcGIS Maps SDK 實務，我目前不會假裝已符合全部條件。不過我的 Python、API、PostgreSQL、QGIS 和空間資料處理基礎相近，因此希望了解是否有初階技術職、圖資自動化任務，或由現有技能切入全端團隊的路徑。

可以接受專案助理工作嗎

我能配合必要的資料整理、文件與使用者溝通，但希望主要成長仍在 GIS 資料處理、程式自動化或系統開發。如果職務長期以行政和客服為主，和我的職涯方向不太一致；若有實際技術任務及明確轉任機制，我願意進一步評估。

你沒有 ArcGIS Pro／ArcGIS Server 經驗

我主要使用 QGIS，熟悉圖層、坐標、GeoJSON、屬性與空間呈現。ArcGIS 生態系是需要補強的工具差異，我會先掌握公司常用工作流、服務層與資料庫結構，再用具體任務學習，不會只停留在介面操作。

為什麼想做 GIS

我喜歡的不只是畫地圖，而是讓帶有位置的資料可以被正確解析、查詢、呈現和驗證。碩士研究中，我看到相同數值若時間、位置或基準沒處理好，地圖就會給出錯誤解讀。這讓我想持續做空間資料系統與自動化。

期望薪資

若仍是公開的 GIS 專案助理，區間為 34,000–42,000 元；若談的是開發或資料自動化職務，應依實際技術責任另談。建議先請對方確認職稱、工作內容與核薪範圍，再表達你會依技術比例、培訓及整體福利評估。

Questions to ask

面談一定要問清楚

  1. 正式職稱：今天評估的是 GIS 專案助理、圖資處理，還是其他技術職？
  2. 實際比例：程式開發、自動化、GIS 分析、資料整理、文件和客服各占多少？
  3. 技術任務：新人前三個月會不會寫程式、碰 API/資料庫，或只使用現有系統？
  4. 技術棧：汐止團隊使用哪些 .NET、Vue、ArcGIS、QGIS、Python、MS SQL/PostgreSQL 工具？
  5. 帶領方式：是否有技術主管、code review、Git 和測試流程？
  6. 轉任機制：若從專案助理進入，轉向工程職的條件、時間與過往實例是什麼？
  7. 標案工作：政府專案文件、會議、驗收與加班大約占多少？
  8. 待遇：依實際職稱確認薪資、獎金、試用期、專案聘期與調薪。
