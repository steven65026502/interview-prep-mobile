Project story

把海洋資料論文講成 AI 工程能力

我的論文不是訓練生成式 AI，而是建立動態海洋資料的品質監測系統。真正可轉移的能力有四個：第一，將多來源資料清理並對齊時間、位置和語意；第二，以 PostgreSQL 與 API 保存及查詢結果；第三，用固定樣本和外部觀測驗證系統；第四，保留限制與有號差值，避免把畫面看起來合理當成結果正確。

這和醫療 AI 的連結是，模型輸出也需要資料來源、權限、日誌、測試集、人工覆核與持續監測。我的現階段強項是資料與後端可靠性；模型微調和推論部署則是我希望在職務中補強的部分。

被問「論文是不是靠 AI 做的」

我有使用 AI 協助找方向、整理程式和檢查文字，但研究問題、資料來源、方法選擇、數值核對和最後判讀由我負責。AI 產出不會直接成為結論，我會回到官方規格、原始資料、程式測試和實際輸出驗證。這也是我認為醫療 AI 必須建立評測、引用、權限和人工覆核的原因。

作品要展示哪五張
  1. 研究問題：品質結果難保存、查詢與重現。
  2. 系統架構：Python → PostgreSQL → Flask API → QGIS。
  3. 資料庫/API：固定查詢與唯讀角色。
  4. 驗證：114 組一致性與 11 站外部比對。
  5. 限制：資料語意、觀測範圍與不能過度宣稱。

  • process、port、環境變數、檔案權限和 log。

  • 部署要有版本、回滾、監測與敏感資訊管理。
醫療 AI 可靠性
  • 病歷與個資不得任意送到外部服務，遵循最小權限與用途限制。
  • 輸入去識別化、輸出保留來源與版本、所有操作可稽核。
  • 高風險建議需人工覆核，不讓模型直接取代臨床決策。
  • 測試不只看平均正確率，也看錯誤類型、族群差異與失敗時處置。

Interview Q&A

高機率問題與回答方向

你沒有 LLM 微調經驗，為什麼適合

我不會把自己說成已能獨立負責模型後訓練。我的直接優勢是 Python、PostgreSQL、API、資料流、log 和驗證，這些正是 AI 模組落地不可缺的工程層。我會先能貢獻資料與後端整合，同時用固定小模型、RAG 範例和 Docker 補齊推論部署，再在團隊指導下進入微調。

如何降低醫療 AI 幻覺

先限制任務與資料範圍，使用經核准知識庫和權限過濾；要求來源引用並驗證引用是否真的支持答案；資料不足時拒答或轉人工；建立固定測試集和回歸測試；高風險輸出由醫療人員覆核；保存模型、prompt、檢索內容與操作日誌。

API 要如何設計得可靠

先定義 schema、驗證輸入、清楚使用 HTTP 狀態碼；設定 timeout、有限 retry、idempotency 與 rate limit；敏感操作需要認證授權；錯誤訊息不洩漏敏感資料；保存 correlation ID、模型版本與關鍵 log，並提供 health check 和回滾。

你怎麼使用 AI 工具

我把 AI 當成加速器，不當成證據來源。工作流程是先定義問題與驗收條件，讓 AI 提供候選方案，再讀程式、跑測試、比對原始資料與官方文件。涉及敏感資料時不直接上傳；所有修改保留版本與可回復性。

能否接受一年一聘與輪班

不要立刻承諾。可回答：「我願意了解專案聘用方式，也重視這份工作的技術內容。想先確認 2026 年底後的續聘預算、評估標準、過往續聘比例，以及晚班、假日班與跨院支援的實際頻率，再做完整判斷。」

期望薪資

公開資訊為月薪 63,000 元以上。可回答希望依公告起薪、實際技術責任、輪班與聘期制度討論；不需要主動報低於公告的數字。進一步確認固定薪、加班、年終、績效與續聘後調薪。
