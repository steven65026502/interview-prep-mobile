API 有成功回應，但少了一個欄位？

我會先區分整個請求沒有回來，還是回應成功但欄位缺少。接著對照規格和原始 JSON，檢查資料來源、查詢條件、序列化或例外處理。必填欄位缺失要明確報錯或隔離，選填欄位依規格處理，不直接補 0。

下面假設規格要求 value 必填且不可為 null，但允許 0。in 查鍵是否存在；is None 查空值。這段只做示範，實務還需要型別與範圍驗證。

def require_value(payload):
    if "value" not in payload:
        raise ValueError("missing value")
    if payload["value"] is None:
        raise ValueError("null value")
    return payload["value"]

assert require_value({"value": 0}) == 0
assert require_value({"value": 12}) == 12
for bad in ({}, {"value": None}):
    try:
        require_value(bad)
    except ValueError:
        pass
    else:
        raise AssertionError("must reject")

為什麼不是加 sleep？sleep 不會把缺掉的欄位補回來。只有已確認的非同步完成等待，才討論有期限的輪詢或完成通知。p50/p90 是延遲分布，也不會指出缺值原因。

什麼時候可以重試？

連線逾時或暫時性服務失敗才評估有限次重試、退避和總期限。資料格式不符、權限不足或參數錯誤，通常要修正原因，不是一直重送。寫入操作要確認冪等設計，避免第一次其實成功，重送卻建立第二筆。HTTP 冪等語意

我會保留請求識別、時間、狀態與必要錯誤訊息，不把 token 或完整個資寫進 log。先確認是否能安全重試，再加重試策略。

Python 暖身：統計每種 HTTP 狀態碼出現次數

輸入整數列表，輸出字典。例如 [200, 500, 200] → {200: 2, 500: 1}。先自己寫，再看答案。

答案與測試
def count_status(codes):
    counts = {}
    for code in codes:
        counts[code] = counts.get(code, 0) + 1
    return counts

assert count_status([]) == {}
assert count_status([200, 500, 200]) == {
    200: 2, 500: 1
}

get(code, 0) 在鍵不存在時取 0，再加一；不是把 API 缺值當 0。走訪 n 筆，字典操作平均為常數時間，整體平均 O(n)，額外空間隨不同狀態碼數量增加。Python 資料結構

函式少寫 return，會怎樣？

一般 Python 函式執行到底沒有 return，回傳 None；print 只印出內容，不等於回傳。先找出每個分支是否有明確輸出，並為正常、缺值、空列表各寫一個測試。不要把本地函式的 None 一律說成網路丟包。

TCP、UDP、HTTP 有什麼不同？

TCP 提供可靠、有序的位元組串流；UDP 傳送獨立資料報，本身不保證到達或順序。HTTP 定義請求與回應語意，層次不同；HTTP/3 使用基於 UDP 的 QUIC，所以不是所有 HTTP 都只靠 TCP。

TCP 層可靠不代表業務資料欄位一定完整。伺服器完全可能可靠地送回一份缺欄位的 JSON。HTTP 與連線

MVC 是什麼？你專案有用嗎？

Model 處理資料與業務邏輯，View 呈現，Controller 接收輸入並協調處理。這是分工概念，不只是一個框架名字。

我的專案能說明資料處理、API 路由與 QGIS 呈現的分工，但我不會直接宣稱完全照 MVC 框架實作。我可以先畫出實際模組，再討論哪些責任應拆開。

API 查詢慢，你怎麼找原因？
  1. 先確認是哪個端點、條件、資料量、同時使用人數，並重現問題。
  2. 量測 API 總耗時與資料庫查詢耗時，分辨 SQL、傳輸或序列化。
  3. 查看 SQL 執行計畫與篩選條件；不要沒量測就替每個欄位加索引。
  4. 評估限制日期範圍、分頁、只選需要欄位，再視證據考慮索引或快取。
  5. 同條件重測，並確認回傳資料仍正確。

如果沒做過壓測，就說「這是我會採用的查核流程」，不要自稱支援萬人流量。

C/C++ 不熟，或現場題寫不出來？

我主要使用 Python，C/C++ 的實務還需要補強。這題我先確認輸入輸出和邊界情況，可以先用 Python 或偽碼說明解法嗎？我會先寫最簡單可行版本，拿小例子逐步測，再討論複雜度。

允許使用 AI 與否先問清楚；不會的語法可以坦白，但不要停止解釋思路。先練 list、dict、迴圈、函式與例外，今晚不用硬背高難度演算法。
